# Специфікація: datakom-exporter

## Мета
Prometheus-експортер для контролерів генераторних установок Datakom D-300 / D-500 / D-700 MK3
(і D-509 MK3, якщо він виявиться тієї ж родини) через Modbus TCP. Замінює textfile-скрипти з
`legacy/`, що писали метрики у файл для node-exporter.

## Функціональні вимоги

### Збір даних
- F1. Протокол Modbus TCP реалізує бібліотека **pymodbus** (≥ 3.0); власної реалізації протоколу немає.
- F2. Лише читання holding-регістрів (FC03). Жодних запитів на запис; регістри 8193 (емуляція
  кнопок) і 8210 (hard reset) ніколи не читаються й не пишуться.
- F3. Запит — не більше 16 регістрів (обмеження контролера). Адреси групуються в блоки
  (`registers.plan_blocks`), невикористані регістри всередині блоку допустимі.
- F4. Карта регістрів — документ Datakom «500-MODBUS» (`src/datakom_exporter/registers.py`,
  `docs/GENERATOR_MODBUS_CONTEXT.md`). 32-бітні значення — два регістри; порядок слів
  налаштовується (`low_first` підтверджено на D-300 MK3, `high_first` — за мануалом).
- F5. Регістри розбиті на **групи опитування** з власним інтервалом; вимкнена група не читається
  і не експортується:

  | Група | За замовч. | Вміст |
  |---|---|---|
  | `live` | кожен скрейп | генератор U/I/kW (по фазах і загальна)/kVA/PF/Hz, батарея, зарядний вхід, тиск масла, температура ОР і масла, паливо, rpm, статус, режим, таймер стану |
  | `mains` | кожен скрейп | мережа U і Hz (CT на генераторі: струму/потужності мережі немає) |
  | `flags` | кожен скрейп | прапорці функцій 11555 (аварія мережі, контактори, auto ready, зведені аварії…) |
  | `alarms` | 60 с, лише при активній аварії | таблиці аварій shutdown / loaddump / warning |
  | `counters` | 300 с | мотогодини, запуски, прокрутки, on-load, kWh, години до сервісу |
  | `info` | 3600 с | ID контролера (10609), версії HW/SW |
  | `extended` | вимкнено | струм/потужність/PF/kVA/kWh мережі, лінійні напруги, реактивна потужність, kVArh, години/дні від сервісу, дні до сервісу |

  Склад груп за замовчуванням визначає дешборда `dashboards/generator.json`: кожен її запит
  повинен мати дані з груп за замовчуванням (перевіряється тестом).
- F6. Значення повільних груп між читаннями віддаються з кешу в пам'яті.
- F7. Скрейпи протягом `min_poll_interval` (5 с) використовують одне опитування (HA-пара Prometheus).
- F8. Після втрати з'єднання кеш скидається: застарілі значення не експортуються; після
  відновлення всі групи читаються одразу. Відсутній блок (illegal address) прибирає лише свої значення.
- F9. Недоступний контролер коштує один таймаут підключення на скрейп, а не таймаут на кожен блок.
- F10. Схема **AMF**, трансформатори струму на виході генератора: струм, потужність, PF і енергія
  вимірюються лише для генератора; для мережі — напруга, частота і стан через прапорці функцій.
- F11. Таблиці аварій (3 запити) читаються лише коли прапорець `any_alarm` (біт 54) = 1, і тоді
  на кожному опитуванні; також при зміні зведених прапорців аварій (біти 50, 51, 52, 54).
  Без активної аварії вони вважаються нульовими. Без групи `flags` — просто за інтервалом.

### Експорт
- E1. HTTP `/metrics` (prometheus_client), порт 9725 за замовчуванням. Prometheus скрейпить
  експортер напряму; textfile collector не використовується.
- E2. Метрики `genset_*` у одиницях SI/техн. одиницях (В, А, кВт, кВА, кВАр, Гц, бар, °C, %, год),
  без ручного масштабування в дешборді. Мітки `source="mains|genset"`, `phase`.
  Лічильники — тип counter з суфіксом `_total`.
- E3. Службові метрики: `genset_modbus_up`, `genset_modbus_failed_blocks`,
  `genset_modbus_poll_duration_seconds`, `genset_modbus_poll_timestamp_seconds`,
  `genset_modbus_group_last_read_timestamp_seconds{group}`, лічильники опитувань/запитів/помилок.
- E4. `genset_controller_info{model,device_identity,hw_version,sw_version,word_order}`.
- E5. Аварії: `genset_alarms{class}` (кількість), `genset_alarm_active{class,bit,name}` (біт 0 = LSB
  першого регістра, назва — з «List of alarm bits» 500-MODBUS).
- E8. Значення аналогових датчиків `0x7FFF` («датчик не встановлений») не експортуються.
- E7. Прапорці функцій: `genset_flag{flag}` 0/1 для 112 названих бітів (500-MODBUS, «List of
  function flags»); `genset_operation_timer_seconds` (10606).
- E6. Старі метрики `gen_*` не експортуються.

### Алерти
- A1. Grafana-managed правила в `alerts/generator-alerts.json` (одна група, фіксовані uid
  `datakom-*`, мітки `group=power` → Telegram, `severity=critical|warning`), завантаження —
  `alerts/upload.py` через provisioning API Grafana.
- A2. Набір: аварія мережі, двигун працює, генератор під навантаженням, аварії контролера
  (з назвою), не в AUTO, батарея поза 11.9–14.8 В, паливо < 25 %, сервіс 1 < 10 год (сервіси 2, 3 — ні), експортер
  недоступний, контролер недоступний. Призупинені за замовчуванням: аварії контролера (дублює
  правило палива) і сервіс. Напругу мережі не алертимо: стан мережі — з контролера (`mains_fail`),
  напругу моніторять інші системи.
- A3. Запит кожного правила — простий селектор метрики експортера (як у дешборді, E2);
  пороги — у виразах Grafana; допоміжні запити-умови — лише `max by (instance, job) (<селектор>)`.
  Правила не дублюють одне одного. Приклад тих самих правил для Prometheus Alertmanager — лише в README.

### CLI
- C1. `datakom-exporter serve` (за замовч.) — HTTP-сервер.
- C2. `probe` — ID, версії, сирі 32-бітні пари, здогадка порядку слів, перевірка правдоподібності.
- C3. `dump` — повний знімок регістрів у JSON-фікстуру для тестів (stdout або `--out`).
- C4. Кожна опція має змінну оточення `DATAKOM_*`. Адреса контролера (`DATAKOM_HOST`) обов'язкова,
  значення за замовчуванням немає.

## Нефункціональні вимоги
- N1. Платформа: Raspberry Pi (Raspberry Pi OS / Debian), Python ≥ 3.9, systemd.
- N2. **Мінімум записів на SD-карту**: експортер не пише файлів; systemd-юніт з `DynamicUser`,
  `ProtectSystem=strict`, без State/Cache/Logs-каталогів; `PYTHONDONTWRITEBYTECODE=1`;
  байт-код компілюється під час встановлення; pip без кешу.
- N3. Журнал: лише старт і переходи «контролер доступний / недоступний» (WARNING), rate limit у юніті.
- N4. Навантаження на контролер: звичайний скрейп — 7 запитів (`live` + `mains` + `flags`);
  раз на 5 хв +2 (лічильники); таблиці аварій +3 лише при активній аварії. При скрейпі раз на
  30 с — у середньому 14.4 запиту за хвилину без аварій.
- N5. Безпека юніта: без привілеїв, обмежені address families і syscalls, `MemoryMax`.
- N6. У репозиторії немає паролів, реальних IP-адрес і адрес хостів інфраструктури
  (у документах — плейсхолдери `<controller-ip>`, `<exporter-host>`).

## Тестування
- T1. Unit-тести карти регістрів, декодування, плану блоків, розбору конфігурації.
- T2. End-to-end: JSON-фікстури → Modbus TCP-сервер pymodbus (`SimDevice`) → експортер →
  розбір відповіді `/metrics`. Усі `tests/fixtures/*.json` і `tests/fixtures/recorded/*.json`
  перевіряються автоматично (очікувані значення + правдоподібність).
- T3. Поведінка: недоступний контролер, неправильний unit id, відсутній блок, відновлення,
  кеш, паралельні скрейпи, розклад груп, відсутність запису у файли (audit hook), відсутність
  write-запитів.
- T4. Відповідність дешборди: кожен запит `dashboards/generator.json` — простий селектор метрики
  `genset_*` без арифметики (нормалізація лише в експортері) і має дані з груп за замовчуванням.
- T6. Відповідність алертів: запит A кожного правила — простий селектор з даними з груп за
  замовчуванням, прапорці існують у `FUNCTION_FLAGS`, uid унікальні, посилання на панелі дешборди.
- T5. Live-тести (`pytest -m live`, `DATAKOM_LIVE_HOST`) для реального контролера, лише читання.

## Поза межами
- Керування контролером (старт/стоп, кнопки, скидання) — ніколи.
- Modbus RTU / RS-485, шлюзи.
- Кілька контролерів в одному процесі (запускається окремий екземпляр на контролер).
- Розшифровка назв окремих бітів аварій (немає таблиці для D-509).
